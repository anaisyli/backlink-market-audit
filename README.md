# 外链平台调查 · 使用说明

给一个外链平台（卖外链位的网站）的网址，产出一份能直接拿去决策的看板：**有多少站、质量如何、多贵、哪个行业值得投、跟另一个平台比谁划算。**

本文件是"怎么用"的说明书。技术细节在 `SKILL.md`，字段定义在 `references/data-schema.md`，各平台的具体套路在 `references/platform-playbook.md`。

---

## 一、你要给什么

只有 **2 个必填**，其余选填但会明显影响结论质量。

| 字段 | 必填 | 举例 | 不给会怎样 |
|---|---|---|---|
| **平台网址** | ✅ | `linkhouse.net`、`cp.adsy.com`、`collaborator.pro` | 没法开始 |
| **登录方式** | ✅ | Google 一键 / 邮箱密码 / 邀请码 / 不用登录 | 我会先猜，猜错要多花一轮 |
| 账号 | ○ | `xxx@gmail.com` | 只用来判断用哪种登录；**密码不要写进任何文件** |
| 目标行业 / 关键词 | ○ | `crypto`、`finance`、`工业设备`、`阀门` | 只出全库画像，说不出"你要的那一类值不值得投" |
| 预算区间 | ○ | `≤$50/条`、`$100–200` | 交叉分析按默认档位给（$25/50/100/200/500） |
| 要不要对比 | ○ | `跟 Adsy 比`、`跟上次 Linkhouse 那份比` | 不生成对比区 |
| 交付格式 | ○ | HTML 看板 / 加一份 Excel | 默认单文件 HTML 看板 |
| 币种 / 语言 | ○ | `€`、英文报告 | 默认 `$` + 中文 |

### 账号密码怎么处理

**不要发密码给我。** 正确做法是我起一个专用 Chrome 目录（`~/.workbuddy/chrome-profile-<平台名>`），弹出窗口后**你自己登录一次**，登录态留在磁盘上，之后几百次采集全部免登录复用。

- 一次登录，后续都复用；下次调查同一个平台直接说"用上次那个登录态"。
- `cookies.json` 这类文件不会放进交付目录，也不会进任何发布上线的包。
- 如果你已经在日常 Chrome 里登录了，也可以告诉我"用我本机 Chrome 的登录态"，我改从现有浏览器读。

## 二、怎么跟我说（可直接复制）

### 1. 最省事的一句话

```
调查一下 https://xxx.com 这个外链平台的资源，出个看板
```

就够了。我会先探路、探不到再回来问你登录方式。

### 2. 完整版（推荐，一次说清，少来回）

```
帮我调查这个外链平台，出一份看板：

- 网址：https://app.xxx.com/market
- 登录：Google 一键（账号 xxx@gmail.com），密码不发你，弹窗我自己登
- 重点行业：crypto 和 finance
- 预算：单条不超过 $150
- 对比：跟 Adsy 比一下谁划算
- 交付：HTML 看板 + 一份 Excel
```

### 3. 双平台对比（只想要结论，不要两份报告）

```
这两个平台哪个更值得投：A（网址…）和 B（网址…）。
我主要做 XX 行业，单条预算 ≤$100，给我一份对比看板，直接说低预算该选哪个。
```

### 4. 数据我已经有了，只要看板

```
这是我抓的站点明细 <文件路径>，字段是 xxx / xxx / xxx，
直接跑分析出看板，平台叫 XXX，总量是 N。
```

（把 `sites.jsonl` 或 csv 丢给我即可，我会用 `--peek` 认字段再写映射。）

### 5. 只想看某个垂直行业值不值得投

```
平台网址…，我只关心 crypto 这类站在这个平台上有多少、多贵、DR 够不够。
不用出全库报告，给我这一类的数字 + 结论就行。
```

### 6. 更新旧报告

```
上次那份 Linkhouse 看板是 9 月的，重新采一遍，跟上一次的数字做对比，标出变化。
```

### 说话时最影响结果的三件事

1. **说清"判断什么"**——"这平台值不值得投"和"这平台 crypto 池子有多大"，我会走不同的采集路径。
2. **给预算**——没有预算，价格分析只能给分布，给不出"该选哪档"。
3. **说要不要对比**——对比要额外采一个平台，成本翻倍，别等我做完才说。

## 三、我拿到之后会做什么

| 步骤 | 我做什么 | 你要做什么 |
|---|---|---|
| 0 摸入口 | 分辨宣传站 vs 真市场（`xxx.net` 多半是 WordPress 门面，市场在 `app.xxx.co`） | — |
| 1 探接口 | 打开页面抓它自己的 XHR/Fetch，找列表接口 + 计数接口，打印字段名 | — |
| 2 登录 | 起专用 Chrome 窗口 | **在弹出的窗口里登录一次**（约 1 分钟） |
| 3 摸分类 | 确认分类数量/ID/名字、筛选参数格式、计数入口 | — |
| 4 计数 | 逐分类调计数接口，拿精确供给量 | — |
| 5 抽样 | 每分类等距取页，目标全库 8,000–10,000 条 | — |
| 6 分析 | 归一化 → 分位数/分档/交叉条件/语言结构 | — |
| 7 出看板 | 生成单文件 HTML，截图自查一遍再交给你 | 看一眼，说哪里要改 |

大致耗时：接口型平台（A 类）**30–60 分钟**；只有"筛选后总数"的平台（Adsy 那种，每查一条要 1 分钟）**1–3 小时**，我会后台跑；纯人工询价的平台（D 类）做不了全库，会先劝退你。

## 四、交付物

```
<平台名>-audit/
├── index.html          ← 看板，双击就能开，单文件无外链
├── profile.json        ← 归一化后的全部数据（看板唯一输入，可手改重渲染）
├── sites.jsonl         ← 站点明细原始数据
├── counts.json         ← 平台精确计数（分类 × 总量/英语/折扣/投放形式）
└── notes.md            ← 口径说明 + 平台接口/参数/坑（下次接同平台省一半时间）
```

看板里有这些板块：

- 顶部 KPI（总量、英语占比、价格中位、DR 中位、流量中位、覆盖率）
- **可拖的权重滑杆** + 质量×价格气泡散点图（左上角是"又便宜又权威"的甜点区）
- 价格结构堆叠条（每个分类的低价供给厚度）
- 可排序总表（每个分类一行 × 全部指标，含"每 $100 得多少 DR"）
- 四个榜单（最划算 / 最不值 / 供给最多 / 流量最大）
- **跨平台对比区**（供给规模、价格分布、质量分布、流量分布、同样预算能买到什么）
- 口径与限制（哪些精确、哪些抽样、缺失率）

先看样品：`assets/sample-output.html`（Linkhouse 真实数据）、`assets/sample-profile.json`（对应的数据结构）。

## 五、看板怎么读（5 分钟）

1. **先看口径区**。抽样估算的"中位价"和平台精确计数不是一回事。口径不对等时，对比区的数字不能直接相减。
2. **拖滑杆**。把权重从"便宜"往"权威"拖，总表排名会重排——你要的那类站会自己浮上来。
3. **看交叉块**「同样预算能买到什么」。这是最有决策价值的一块：`≤$50 且 DR≥30` 占多少，直接回答"我的预算能买到什么质量"。
4. **只在同类之间比**。`每 $100 得多少 DR` 会偏向便宜但低质的分类，只能当参考，不能单独排序。
5. **表格里 `total` 和 `sample_n` 要一起看**。前者是分类供给量，后者是你实际抽了多少条来估分位数——两个数差太远，说明这一类结论可信度低。

## 六、必须知道的口径红线

| 红线 | 说明 |
|---|---|
| **流量缺失 ≠ 流量为 0** | 很多平台只有部分站有流量数据。缺失必须单列覆盖率，不能当 0 算进中位数（实测能把中位从 1,914 拉到 234）。 |
| **分类 ID 用错是静默失败** | 不报错，只给你别的分类的数据。Linkhouse 的 37 个分类 ID 不连续、没有 13 号。每采一类要抽 3 条人工核对。 |
| **平台分类 ≠ 站点真实主题** | 平台的一级归类经常不准。要判断某站是否真写某个垂直，得抓首页/sitemap 二次验证。 |
| **精确 vs 抽样不能混着说** | 一边"全库"一边"已核验+英语"，数量差 3 倍不是平台差距，是口径差距。 |
| **能服务端精筛就别抽样** | 平台支持价格/DR 区间筛选（Adsy 支持、Linkhouse 不支持）就直接拿精确数。 |
| **凭据不落库** | `cookies.json` 不跟交付物放一起，更不能进发布目录。 |

## 七、不用对话，手动跑

```bash
cd ~/.workbuddy/skills/backlink-market-audit

# 1) 探接口（零依赖，Node ≥22）
node scripts/probe.mjs --url "https://app.xxx.com/market" --profile "<chrome目录>"
#   可选：--wait 15000（SPA 慢）/ --click "button.next"（要交互才发请求）

# 2) 先看字段名，再写映射
python scripts/analyze.py sites.jsonl --peek

# 3) 归一化（--counts 不给，总量会差一个数量级）
python scripts/analyze.py sites.jsonl \
  --platform "Platform" --entry "app.xxx.com/market" \
  --map maps/platform.json --counts counts.json --meta meta.json \
  -o profile.json
#   可选：--currency "€"  --top-segments 20  --bands bands.json

# 4) 出看板（--strict 有缺字段就报错退出）
python scripts/dashboard.py profile.json -o market-dashboard.html

# 5) 跨平台对比
python scripts/make_compare.py a.json b.json -o merged.json \
  --label "Adsy" --note "Adsy 为已核验+英语口径"
python scripts/dashboard.py merged.json -o compare.html
```

**交付前必须实际截图看一眼**（历史教训：语法过 ≠ 能跑）：

```bash
"C:/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu \
  --window-size=1360,3000 --virtual-time-budget=5000 \
  --screenshot="C:/abs/path/shot.png" "file:///C:/abs/path/market-dashboard.html"
```

HTML 文件名用 **ASCII**——中文文件名在预览面板里曾整份不显示。

## 九、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 看板全空、KPI 是 0 | 多半是登录态失效，市场页 302 到 login。重开 Chrome 目录登录一次。 |
| 只采到 20–30 个站 | 分页参数没生效。查 `per_page` 上限和 URL 里的 `page` / `offset` 写法。 |
| 计数和抽样推出的总量差十倍 | `--counts` 没给，或分类 ID 对错了。 |
| 某个分类数据明显不像它 | 分类 ID 错了（静默失败）。抽 3 条核对名称。 |
| 对比区数字差 3 倍 | 口径不对等。看 `note` 是否写清，别直接下结论。 |
| 看板打不开 / 预览空白 | 文件名改成 ASCII；确认是单文件、没引用外部 CDN。 |
| 想上线分享 | 看板是单文件，可以直接发布；**发布前把 `cookies.json`、`sites.jsonl` 从目录里剔掉**。 |

## 十、它做不到什么

- **不能绕过登录和付费墙**。需要付费订阅才能看的库存，只能拿到你账号权限内的数据。
- **不能判断站点真实内容质量**。DR/流量/垃圾分是第三方指标，平台分类经常不准；要确认某站是否真写某垂直，得另外抓首页看。
- **纯人工询价平台（D 类）做不了全库**，只能小样本核对。
- **不做投放后的效果追踪**。这里回答"买之前值不值"，不回答"买了之后排名有没有涨"。
- **数据是采集那一刻的快照**。外链库存变动快，超过一两个月的报告要重采。
